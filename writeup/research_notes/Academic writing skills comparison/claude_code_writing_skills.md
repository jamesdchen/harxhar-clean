## 1. Which official Anthropic skills touch writing, and how are they built?

### Takeaway
Four skills in `anthropics/skills` touch prose: `doc-coauthoring` (a staged human-in-the-loop workflow with a fresh-subagent "Reader Testing" pass), `internal-comms` (a 32-line router to per-genre example files, the same shape as `paper-prose`), `brand-guidelines` (visual, not prose) and `skill-creator` (Anthropic's guidance on writing skills, with an eval and description-tuning harness). None has a sentence-level style catalog, a linter or an eval suite for prose quality. The eval machinery sits in `skill-creator`, not in the writing skills.

### Cited Findings
**doc-coauthoring** (375 lines, 2,466 words, description 428 chars; last commit 2025-12-04; SKILL.md only, with no scripts, references or evals) — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/doc-coauthoring/SKILL.md)
- Trigger: "Use when user wants to write documentation, proposals, technical specs, decision docs… Trigger when user mentions writing docs, creating proposals, drafting specs." The body also lists phrases ("write a doc", "draft a proposal", "write up", "PRD", "RFC") — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/doc-coauthoring/SKILL.md)
- Three stages: (1) Context Gathering (5 meta-questions, an info dump, then 5–10 numbered clarifying questions); (2) Refinement & Structure, per section: clarifying questions, brainstorm 5–20 options, user curation ("Keep 1,4,7,9"), gap check, draft, then iterative refinement with `str_replace` ("never reprint the whole doc"); (3) Reader Testing — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/doc-coauthoring/SKILL.md)
- Reader Testing: "Test the document with a fresh Claude (no context bleed)". Predict 5–10 reader questions, "invoke a sub-agent with just the document content and the question", then run a sub-agent check "for ambiguity, false assumptions, contradictions" and loop back. Exit when "Reader Claude consistently answers questions correctly" — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/doc-coauthoring/SKILL.md)
- Style learning: "Instead of editing the doc directly, ask them to indicate what to change. This helps learning of their style for future sections." If the user edits directly, "mentally note the changes they made" — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/doc-coauthoring/SKILL.md)
- Quality gates: "After 3 consecutive iterations with no substantial changes, ask if anything can be removed". Near completion, re-read for "Anything that feels like 'slop' or generic filler" and "Whether every sentence carries weight" — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/doc-coauthoring/SKILL.md)

**internal-comms** (32 lines, 211 words; examples/ holds `3p-updates.md`, `company-newsletter.md`, `faq-answers.md`, `general-comms.md`; last commit 2026-04-20) — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/internal-comms/SKILL.md)
- Body: "1. Identify the communication type… 2. Load the appropriate guideline file from the `examples/` directory… 3. Follow the specific instructions in that file." If no type matches, "ask for clarification". It ends with a "Keywords" line — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/internal-comms/SKILL.md)

**brand-guidelines** (73 lines) covers colors and typography ("Anthropic's official brand colors and typography… visual formatting"), not prose — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/brand-guidelines/SKILL.md)

**skill-creator** (485 lines, 5,205 words; agents/ `grader.md`, `comparator.md`, `analyzer.md`; scripts/ `run_eval.py`, `run_loop.py`, `improve_description.py`, `aggregate_benchmark.py`, `quick_validate.py`; eval-viewer/; last commit 2026-04-20) — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)
- Description: "the primary triggering mechanism… include both what the skill does AND specific contexts… Claude has a tendency to 'undertrigger' skills… please make the skill descriptions a little bit 'pushy'" — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)
- Progressive disclosure, three levels: metadata (~100 words, always loaded), SKILL.md body ("<500 lines ideal"), bundled resources ("unlimited"). "For large reference files (>300 lines), include a table of contents" — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)
- Writing style: "explain to the model why things are important in lieu of heavy-handed musty MUSTs… If you find yourself writing ALWAYS or NEVER in all caps, or using super rigid structures, that's a yellow flag". Also "Keep the prompt lean. Remove things that aren't pulling their weight… read the transcripts, not just the final outputs" — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)
- "Look for repeated work across test cases… If all 3 test cases resulted in the subagent writing a `create_docx.py`… bundle that script" — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)
- Evals: 2–3 realistic prompts in `evals/evals.json`, run with-skill and baseline in the same turn, draft assertions while the runs are in progress, grade and launch a viewer, then iterate. Blind comparison via `agents/comparator.md` — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)
- Description optimization: 20 queries (8–10 should-trigger, 8–10 should-not, "the most valuable ones are the near-misses"), a 60/40 train/held-out split, "running each query 3 times", up to 5 iterations, "best_description — selected by test score rather than train score to avoid overfitting" — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)
- "Claude only consults skills for tasks it can't easily handle on its own — simple, one-step queries… may not trigger a skill even if the description matches perfectly" — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)
- `quick_validate.py` rejects a description over 1,024 characters: "Description is too long… Maximum is 1024 characters" — [quick_validate.py](https://github.com/anthropics/skills/blob/main/skills/skill-creator/scripts/quick_validate.py)
- Anthropic blog (2026-03-03): skill-creator now writes evals, runs a benchmark mode ("tracks eval pass rate, elapsed time, and token usage") and blind A/B comparator agents. Description tuning "saw improved triggering on 5 out of 6 public skills". It distinguishes "capability uplift" skills from "encoded preference" skills that sequence a team's process — [claude.com blog](https://claude.com/blog/improving-skill-creator-test-measure-and-refine-agent-skills)

**Other repo skills.** `discernment-nudge` (209 lines, added 2026-08-17) appends 2–3 follow-up questions after a substantive draft so the user checks facts and assumptions. It is adjacent to writing but not a prose skill — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/discernment-nudge/SKILL.md). The repo's other skills (docx, pdf, pptx, xlsx, canvas-design, etc.) are format or design skills — [repo tree](https://github.com/anthropics/skills/tree/main/skills)

### Inferences
- `internal-comms` is the closest official analogue to `paper-prose`: a short router that picks one reference file by task type. `paper-prose` follows the same official pattern but reads up to 11 files per branch, where `internal-comms` reads one.
- `doc-coauthoring`'s Reader Testing is the one official mechanism that tests prose against a reader rather than a rule list. `paper-prose` has no equivalent; its branch G is a rule-checklist critic.
- `doc-coauthoring` learns the author's style from his feedback. `paper-prose` takes the opposite and stricter position: author text is copied verbatim (V13), and agent text is not polished before lock (V14). The two do not conflict, but nothing official supports our verbatim and lock rules; they are our own.

### Gaps
- I did not read the full text of the claude.ai built-in docx, pdf and pptx skills. Their names and the best-practices page suggest they are file-format skills with no prose-style content, but I did not verify that line by line.
- No official Anthropic skill for academic or scientific writing was found in `anthropics/skills` or in `anthropics/claude-plugins-official`. A path grep of the latter found only `hookify/skills/writing-rules` and output-style plugins.

## 2. Which community skills exist for prose, editing, academic/scientific writing, LaTeX, "humanizing" and style guides?

### Takeaway
The community writing skills fall into four clusters. (a) Anti-AI-tell editors ("humanizers"): blader/humanizer, avoid-ai-writing, stop-slop, better-writing, unslop, plus many single-language forks. (b) Classic style guides: Strunk's Elements of Style packaged as `writing-clearly-and-concisely`, and beautiful-prose. (c) Academic or scientific manuscript pipelines: K-Dense `scientific-writing`/`peer-review`, Orchestra `ml-paper-writing`, Imbad0202 `academic-paper`, dvdsosa `sciwrite-*`, and Pedro Sant'Anna's econometrics workflow. (d) Meta-skills on writing skills: obra `writing-skills`. Only a few ship behavioral evals: better-writing has a full fixture, held-out split, trigger and claim-invention-judge harness; Imbad0202 has gold sets with a CI lift gate. Most others have no tests, or tests of their scripts only. I found no independent benchmark of any writing skill.

#### Further details by cluster

- **better-writing evals** (details): each fixture is "a text seeded with known AI tells and known facts". The always-on arm puts the whole skill in the system prompt and is "an upper bound"; the progressive arm mimics real loading. The first reference run (skill 1.2.1, 2026-09-28) passed "93/110 always-on and 77/110 progressive, a paired difference of -0.15 [-0.24, -0.05]". A second model call lists invented claims ("a hope restated as something that has happened"). The held-out split has 9 of 22 fixtures, "never-read". The trigger eval "triggered on 30 of 30 should-trigger runs and 0 of 30 should-not"; swapping in an unrelated description "dropped recall to 0 of 6". Pairwise comparison against a no-skill baseline is unlabelled, both orders, "never label which output came from the skill: labelled authorship shifts judge preference by tens of points" — [evals/README.md](https://github.com/forjd/better-writing/blob/main/evals/README.md)
- better-writing fixtures that map onto our rules: `ranking-claims` ("first site", "only office"… must survive: "Trimming a flourish or a qualifier often takes a ranking word with it, and each one is a claim"); `academic-hedge` (passive methods and hedges must survive, "it is important to note" goes); `voice-preservation` and `plain-human` (false-positive regressions: "Voice markers must not move"); `light-edit-contrast` ("The contrast budget applies to text the skill writes, not to a writer's own"); `review-findings` (review mode must quote tells and "does not rewrite": "no run of more than 15 input words") — [evals/README.md](https://github.com/forjd/better-writing/blob/main/evals/README.md)

## 3. What do Anthropic's skill-authoring docs imply for our skill's structure?

### Takeaway
`paper-prose` already follows the core guidance: a short router SKILL.md, references one level deep, files under 100 lines, concrete rewrite pairs and a copyable checklist. The docs point to five concrete gaps:
- the description is 1,060 characters, over the 1,024-character spec maximum, and it summarizes the workflow;
- there are no evals of any kind;
- deterministic checks are greps in prose rather than scripts or hooks;
- the skill carries time-sensitive state ("On 29 Oct 2026 the file does not exist");
- delegation relies on coordinators naming the skill in prompts, although Claude Code can preload a skill into a subagent type.

### Cited Findings
- **Description limits.** "`description`: Must be non-empty, Maximum 1,024 characters… Should describe what the Skill does and when to use it"; "Always write in third person" — [best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices). skill-creator's validator enforces the 1,024 limit — [quick_validate.py](https://github.com/anthropics/skills/blob/main/skills/skill-creator/scripts/quick_validate.py). Claude Code caps "the combined `description` and `when_to_use` text… at 1,536 characters in the skill listing" and advises "Put the key use case first" — [Claude Code skills](https://code.claude.com/docs/en/skills). Our description is 1,060 chars — [SKILL.md](.claude/skills/paper-prose/SKILL.md). `claude plugin validate .claude/skills` passed on 2026-10-29 (local run), so Claude Code does not enforce the 1,024 cap
- **Listing budget.** When many skills are installed, "Claude Code drops some descriptions to fit the listing's character budget… The budget scales at 1% of the model's context window… drops descriptions starting with the skills you invoke least" — [Claude Code skills](https://code.claude.com/docs/en/skills)
- **Length.** "Keep the `SKILL.md` body under 500 lines"; "Once a skill loads, its content stays in context across turns, so every line is a recurring token cost" — [Claude Code skills](https://code.claude.com/docs/en/skills); [best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- **One level deep.** "Keep references one level deep from `SKILL.md`… Claude might use commands such as `head -100` to preview content rather than reading entire files". For files over 100 lines, "include a table of contents" — [best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- **Conciseness.** "Default assumption: Claude is already very smart… 'Does this paragraph justify its token cost?'" — [best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- **Degrees of freedom.** Low freedom ("Run exactly this script") when "Operations are fragile and error-prone; Consistency is critical"; high freedom when "Decisions depend on context" — [best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- **Checklists and feedback loops.** "provide a checklist that Claude can copy into its response and check off". "Run validator → fix errors → repeat… This pattern greatly improves output quality". Its example "Style guide compliance" loop uses STYLE_GUIDE.md as the validator — [best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- **Scripts.** "Prefer scripts for deterministic operations"; utility scripts "Are more reliable than generated code… Ensure consistency across uses". "Plan-validate-execute": write a plan file, validate it with a script, then apply; "Make validation scripts verbose with specific error messages" — [best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- **Time-sensitive content.** "Don't include information that will become outdated"; use an "Old patterns" section instead — [best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- **Terminology.** "Choose one term and use it throughout the Skill" — [best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- **Evals first.** "Create evaluations BEFORE writing extensive documentation"; steps: identify gaps, three scenarios, a baseline without the skill, minimal instructions, iterate. Checklist: "At least three evaluations created; Tested with Haiku, Sonnet, and Opus; Tested with real usage scenarios" — [best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices). Claude A / Claude B: one instance refines the skill, a fresh one uses it on real tasks; "Observe how Claude navigates Skills… Ignored content: If Claude never accesses a bundled file, it might be unnecessary" — [best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- **Engineering blog (2025-10-16).** Progressive disclosure is "the core design principle"; "Start with evaluation"; "Pay special attention to the name and description" — [Anthropic engineering](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)
- **Hooks for must-hold rules.** "Claude skipped a rule that must hold every time: move the rule into a hook… define the hook in the skill's `hooks` frontmatter". Also "Claude Code adds the skill's content to the conversation when the skill is invoked and doesn't re-read the file"; "After compaction… keep only the start of an invoked skill, so put the most important instructions near the top" (the first 5,000 tokens of each skill, with a combined 25,000-token budget) — [Claude Code skills](https://code.claude.com/docs/en/skills)
- **Frontmatter levers.** Claude Code supports `when_to_use`, `paths` ("Glob patterns that limit when this skill is activated"), `context: fork`, `allowed-tools`/`disallowed-tools`, `hooks` and `disable-model-invocation` — [Claude Code skills](https://code.claude.com/docs/en/skills)
- **Subagents.** "Each subagent starts with a fresh, isolated context window. It doesn't see your conversation history, the skills you've already invoked…". The `skills` field preloads skills: "The full content of each listed skill is injected into the subagent's context at startup"; "Built-in agents don't preload skills" — [Claude Code sub-agents](https://code.claude.com/docs/en/sub-agents)
- **Path-scoped rules.** `.claude/rules/*.md` with `paths` frontmatter load "when Claude uses the Read, Write, or Edit tool on a matching file" — [Claude Code memory](https://code.claude.com/docs/en/memory). Sant'Anna scopes his writing rule to `**/*.tex` this way — [writing-with-ai.md](https://github.com/pedrohcgs/claude-code-my-workflow/blob/main/.claude/rules/writing-with-ai.md)
- **Our skill against these points.** `paper-prose` is 103 lines and points one level down to pattern files of at most 75 lines (no ToC needed). Its pattern files carry Instead-of / Write tables (the "examples pattern") and its Step 2 is a copyable checklist — [SKILL.md](.claude/skills/paper-prose/SKILL.md), [V6](writeup/style/patterns/claims/V6-no-after-the-fact-tails.md). Branch F says "On 29 Oct 2026 the file does not exist, so no layer is locked", and Step 2 says "Most automatic checks (C2, C5, C18, C25, C26, `scrub.py`) are not built yet" — [SKILL.md](.claude/skills/paper-prose/SKILL.md). The SKILL.md opens with the author's dated quotes and the trigger history before Step 0 — [SKILL.md](.claude/skills/paper-prose/SKILL.md)

### Inferences
- **Fix the description.** Trim it to 1,024 characters or fewer, e.g. by dropping "It routes each task to… and ends with a self-check" and the coordinator sentence. That keeps it valid outside Claude Code (API, claude.ai upload). Anthropic says "what + when"; obra says "when only". The safe common ground is triggers plus scope exclusions, without the workflow summary.
- **Make subagents preload the skill.** Define a project subagent such as `.claude/agents/paper-drafter.md` with `skills: [paper-prose]`. This replaces "coordinators name it in every drafting subagent's prompt" with a mechanism. It loads only SKILL.md; the branch's pattern files still have to be read.
- **Add `paths`.** `paths: writeup/**/*.tex, writeup/make_*.py` would make the skill (or a companion `.claude/rules/` file) load when an agent edits paper files, including when the conversation has no "write it up" wording.
- **Turn the greps into a hook.** The Detection greps for V2, V6, AP-S and AP-V could run as a PostToolUse hook on Edit/Write of `writeup/rehaul/*.tex`, flagging only (V6 says "flagged for review, never auto-rewritten"). That is the docs' recommended home for rules that must hold every time.
- **Remove dated state.** Replace the dated sentence with a check ("if `writeup/layer_state.json` is absent, no layer is locked").
- **Reduce the id systems.** Our skill uses V, AP-V, AP-S, C, S, L, A and report § ids. The terminology guidance suggests the router name fewer of them; for example, keep C and S codes inside the pattern files.
- **Plan-validate-execute fits V16.** "Same macros, cites, refs, negations, modals, direction words and agents" is checkable by a deterministic diff script over the old and new sentence. It fits the docs' validation loop better than a checklist line.

### Gaps
- The docs do not say whether `.claude/rules/` path-scoped rules load inside subagents.
- No Anthropic doc measures how often Claude actually opens bundled reference files. better-writing's progressive-versus-always-on gap (−0.15 pass rate) is the only measurement found, and it comes from one third-party skill and one model.

- **Provenance gate first.** Step 0 asks "whose text is it?" before any rule applies, and V13/V15 protect author and Overleaf text byte for byte — [SKILL.md](.claude/skills/paper-prose/SKILL.md), [V13](writeup/style/patterns/scope/V13-author-text-verbatim.md). The nearest equivalents are weaker: avoid-ai-writing's "scope authorization" — [SKILL.md](https://github.com/conorbronsdon/avoid-ai-writing/blob/main/SKILL.md); better-writing's light-edit mode ("Every word starts as kept") and its rule that the contrast budget does not apply "to a writer's own" — [SKILL.md](https://github.com/forjd/better-writing/blob/main/skills/better-writing/SKILL.md), [evals](https://github.com/forjd/better-writing/blob/main/evals/README.md); K-Dense's "Only accountable humans may…" — [SKILL.md](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/scientific-writing/SKILL.md)
- **Claim-level rules.** V4 and V5 have no counterpart; the closest is K-Dense's OVERSTATEMENT/CAUSAL regex — [lint_manuscript.py](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/scientific-writing/scripts/lint_manuscript.py). better-writing's `ranking-claims` fixture guards the *opposite* failure, where a rewrite deletes a ranking word that is a claim — [evals/README.md](https://github.com/forjd/better-writing/blob/main/evals/README.md). - **Rules carry their motivation and incidents.** Each pattern has a Motivation section with the real incident (e.g. the false "none significantly" tail, p = 0.035) — [V6](writeup/style/patterns/claims/V6-no-after-the-fact-tails.md). #### Practices to avoid (with evidence)
- **Detector evasion and "humanizing for provenance".** diaiq's skill posts the text to an unauthenticated third-party API to "pass GPTZero, Turnitin" — [SKILL.md](https://github.com/diaiq/claude-skill-humanizer/blob/main/SKILL.md). That runs against K-Dense's confidentiality rule ("Do not send unpublished manuscripts, peer-review or editorial material, sensitive or…"; for reviewer material, "Do not upload it to an external service without the required authorization") — [scientific-writing](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/scientific-writing/SKILL.md). Surface de-AI edits left a Pangram score of "100 % AI-written" — [Sant'Anna](https://github.com/pedrohcgs/claude-code-my-workflow/blob/main/.claude/rules/writing-with-ai.md). better-writing refuses detector scores as a check: optimizing against detectors "rewards worse prose", light AI edits were flagged "38% and 80% of the time", and detectors are biased against learners — [evals/README.md](https://github.com/forjd/better-writing/blob/main/evals/README.md). humanizer's README now says detector evasion "is not a goal" — [CHANGELOG.md](https://github.com/blader/humanizer/blob/main/CHANGELOG.md)
- **Global rhythm or style targets.** humanizer: "Vary sentence length; real writing alternates short and long" — [SKILL.md](https://github.com/blader/humanizer/blob/main/SKILL.md). stop-slop: "Vary rhythm… Two items beat three… No em dashes" — [SKILL.md](https://github.com/hardikpandya/stop-slop/blob/main/SKILL.md). beautiful-prose: "Treat violations as failures", `REGISTER: founding_fathers` — [SKILL.md](https://github.com/SHADOWPR0/beautiful_prose/blob/main/SKILL.md). Imbad0202 Style Calibration learns "sentence rhythm" from past papers — [SKILL.md](https://github.com/Imbad0202/academic-research-skills/blob/main/academic-paper/SKILL.md). Against these: our AP-S says uniform sentence length is "contested and confounded with length: dashboard only, never a gate", and V12 bans global style instructions — [AP-S](writeup/style/patterns/anti-patterns/AP-S-structural-markers.md), [SKILL.md](.claude/skills/paper-prose/SKILL.md). ARS's own anti-pattern says "do not pad, split, or vary length to satisfy a template" — [SKILL.md](https://github.com/Imbad0202/academic-research-skills/blob/main/academic-paper/SKILL.md)
- **LLM self-scoring as a gate.** stop-slop's "Below 35/50: revise" — [SKILL.md](https://github.com/hardikpandya/stop-slop/blob/main/SKILL.md); claude-blog blocks below 90/100 — [Analytics Vidhya](https://www.analyticsvidhya.com/blog/2026/08/top-5-claude-writing-skills/). Neither score is calibrated. better-writing's README says judges "agree with human writing preferences only about three quarters of the time" and prefer "low-perplexity text and the first item shown" — [evals/README.md](https://github.com/forjd/better-writing/blob/main/evals/README.md)
- **Absolute bans that fire on good human prose.** better-writing found its em-dash ban fired 11 times on Jerome K. Jerome, so it kept the ban fixture-level — [evals/README.md](https://github.com/forjd/better-writing/blob/main/evals/README.md). sciwrite-prose: "The dash, colon, semicolon and parentheses are tools"; "Methods may use the passive voice"; "Repeating a keyword is required" — [SKILL.md](https://github.com/dvdsosa/scientific-writing-skills/blob/master/skills/sciwrite-prose/SKILL.md). Our Step 2 line "AP-S: no em dash" is stricter than AP-S's own "Rate… against the corpus p10–p90 band" — [SKILL.md](.claude/skills/paper-prose/SKILL.md), [AP-S](writeup/style/patterns/anti-patterns/AP-S-structural-markers.md)
- **Claim-inflating "assertive vocabulary".** Orchestra/Lipton: "Eliminate hedging: Drop 'may' and 'can'…", "combine/modify/expand → develop/propose/introduce" — [SKILL.md](https://github.com/Orchestra-Research/AI-Research-SKILLs/blob/main/20-ml-paper-writing/ml-paper-writing/SKILL.md). This runs against V7 (hedges belong on interpretation) and V4/V5, and against K-Dense's "Do not convert… non-significance into equivalence" — [scientific-writing](https://github.com/K-Dense-AI/scientific-agent-skills/blob/main/skills/scientific-writing/SKILL.md)
- **Over-long monolithic skills.** ml-paper-writing is 982 lines; academic-paper is 662 lines with a 1,003-char description listing 11 modes; avoid-ai-writing's `SKILL.full.md` is 18,136 words. The docs ask for under 500 lines — [best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices); [PROOF.md](https://github.com/conorbronsdon/avoid-ai-writing/blob/main/PROOF.md)
- **Rules fetched at run time.** Vercel's writing-guidelines says "Fetch fresh guidelines before each review" from a mutable raw URL — [SKILL.md](https://github.com/vercel-labs/agent-skills/blob/main/skills/writing-guidelines/SKILL.md). That makes outputs unreproducible and opens an injection path; Anthropic advises auditing skills that "connect to external networks" — [Anthropic engineering](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)
- **Nuance and exemption clauses inside prohibitions** — obra: "'Don't X unless it matters' reopens the negotiation"; "Exemption clauses don't scope" — [writing-skills](https://github.com/obra/superpowers/blob/main/skills/writing-skills/SKILL.md). Several of our lines take this form (AP-S: "outside the conclusion where a plain form exists"; Step 0's exemptions). Our V6, though, is already a recipe ("state it as a claim of its own… or delete it") — [V6](writeup/style/patterns/claims/V6-no-after-the-fact-tails.md)
- **A workflow summary in the description** — obra's single-case evidence that agents follow the summary instead of the body — [discovery.md](https://github.com/obra/superpowers/blob/main/skills/writing-skills/references/discovery.md). Ours contains "routes each task… and ends with a self-check" — [SKILL.md](.claude/skills/paper-prose/SKILL.md)

### Inferences
- **Priority order for borrowing**, from cheapest to most valuable:
  1. Trim the description to 1,024 characters or fewer, without the workflow summary.
  2. Remove the dated "On 29 Oct 2026" state.
  3. Add a `paper-drafter` subagent type with `skills: [paper-prose]`, and a read-only critic type for branch G.
  4. Bundle the existing greps as one script, with a V16 diff checker.
  5. Write 6–10 fixtures from the incidents already logged in the deliberation records, plus a 20-prompt trigger set, following better-writing's design (required and banned strings, held-out split, no-skill baseline, repeats).
  6. Add a reader test to branch G.
- **Measure our biggest structural risk first.** better-writing measured a 0.15 pass-rate loss from loading references on demand. Our router depends on agents actually reading the branch files, so this should be measured before more patterns are added.
- **The humanizer genre does not transfer to us.** It targets reader-perceived AI tells in general prose, while our failure modes (false universals, unlicensed verdict words, typed numbers) are claim-validity failures. The academic skills that come closest to ours (K-Dense, Sant'Anna) solve the problem with records and scripts, not style rules.
