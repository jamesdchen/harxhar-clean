# Hierarchical, outline-first text generation with LLMs (beats -> outline -> prose) and the human writing methods it mirrors

Research date: 2026-10-28. Verification depth for each source: **[full text]** means the paper's HTML/ar5iv full text was read (via a model-summarised fetch). **[abstract]** means only the arXiv abstract page was read. **[secondary]** means a blog, review or handout summarised the source.

## 1. Research systems: hierarchy levels, how each level is conditioned on the one above, drift control, evaluations

### Takeaway
All of the successful long-form systems since 2018 follow the same three steps: (a) build a compressed plan small enough to fit in the context window, (b) generate each unit conditioned on the global plan, its own plan node and nearby already-written text, (c) run a final pass that removes duplication and checks citations. Measured gains over flat generation are large for coherence and plan relevance (+14 to +28 points absolute in human pairwise studies of stories; STORM's human-rated organization 4.00 vs 3.25). The plan does **not** by itself fix factual grounding. STORM's verifiability was unchanged, and leaf-level outline items are the ones most often ignored.

**Dramatron detail** — [ar5iv 2209.14958](https://ar5iv.labs.arxiv.org/html/2209.14958)
- Users can regenerate, continue or manually edit at every level, and can move back up the hierarchy (e.g., rewrite the logline after a plot exists). The paper does **not** specify a mechanism that propagates an upper-level edit downward. Later prompts simply read the current edited text.
- Scenes were generated in parallel. One participant (p1) said, "From the scene beats, it has no idea of what the previous dialogue contained." The fix was to add the current and previous scene beats to each dialogue prompt (Table 1 change log).
- Participants valued seeing the structure early ("I can see the narrative more clearly"; "you can do as much human-ing as you want at any level"). **The plot outline was the least-edited layer.** Users mostly deleted or rewrote location descriptions, loops and character descriptions.
- Weaknesses: dialogue was too literal and lacked subtext; generation looped (every participant saw it); "character journeys are not complete"; gender bias; more than half of survey respondents felt no ownership; playwrights disliked starting from a top-down logline. 92% were surprised by outputs and 77% enjoyed using it.

**STORM detail** — [arXiv html 2402.14207](https://arxiv.org/html/2402.14207)
- Outline quality (GPT-4): heading soft recall 92.73 (STORM) vs 87.66 (direct generation); heading entity recall 45.91 vs 34.78. Removing the simulated conversations dropped entity recall to 39.30.
- Article ROUGE-1: STORM 45.82 vs **w/o outline stage 26.77**, oRAG (outline-driven RAG) 44.26, direct generation 25.62. In the extracted Table 2, the w/o-outline variant's LLM-judged *Organization* (4.87) was slightly **above** STORM's (4.82), so the LLM judge did not reward the outline stage on organization.
- Citation recall 84.83%, precision 85.18%: about 15% of sentences are not supported by their citations. The most common error in the manual analysis is "improper inferential linking", where the model draws unverifiable connections between unrelated facts ("red herring" / over-association).
- Wikipedia editors (20 pairs, 1–7 scale): organization 4.00 vs 3.25 for oRAG (p = 0.005); coverage 4.00 vs 3.58 (p = 0.084); **verifiability 3.80 vs 3.85 (p = 0.843, no difference)**; pairwise preference 26–14 for STORM. 7 of 10 editors said the outputs sounded "emotional" or "unneutral", a bias carried over from the sources.

**AutoSurvey detail** — [arXiv html 2406.10252](https://arxiv.org/html/2406.10252)
- Citation recall/precision at 64k tokens: AutoSurvey 82.25 / 77.41 vs naive RAG 68.79 / 61.97 vs human 86.33 / 77.78. Content average: 4.62 vs 4.19 vs 4.88. Naive RAG gets worse as length grows. AutoSurvey stays roughly flat.
- Ablations: without retrieval, recall fell 83.48 -> 60.11 and precision 77.15 -> 51.65. **Without the reflection pass, citation metrics barely moved** and content average went only 4.57 -> 4.56; structure/coherence suffered most. Going from 1 to 5 iterations gave diminishing returns after the second.
- Of 100 unsupported claims: overgeneralization 51%, misalignment 39%, misinterpretation 10%. The authors conclude the model "still leans heavily on parametric knowledge".
- Cost for a 32k-token survey: about 3.0M input / 113K output tokens ($0.89 Claude-Haiku to $33.48 GPT-4).

**DOC detail and limitations** — [ar5iv 2212.10077](https://ar5iv.labs.arxiv.org/html/2212.10077)
- Ablation (10 stories): removing the detailed outliner lowered relevance 64.7 -> 41.2. Removing the controller lowered relevance 73.5 -> 52.0. Leaf-level relevance rose from 37.8% without the controller to 58.5% with it.
- Limitations stated by the authors: "DOC often fails to follow low-level outline items"; leaf detail is uneven (some items too vague, others over-expanded); outline errors cascade into drafting; factual consistency over long passages remains a problem; stronger control produces repetitive, less creative text; generation is 2–3× slower than Re3.

**AI Scientist write-up failure modes** — [arXiv html 2408.06292](https://arxiv.org/html/2408.06292)
- It hallucinated hardware details (claimed V100 GPUs when H100s were used). When ablations were requested but not run, an early version produced an entire ablation table. The fix was an instruction to include only directly observed results.
- It references figures incorrectly, leaves run artifacts ("Run 2") in the text, presents negative results as positive, and struggles to compare magnitudes of numbers. In the case study, though, the main table's numbers matched the logs and were rounded correctly.
- It often fails to compile LaTeX (GPT-4o). Its bibliographies are small (9 entries in the case study).

### Inferences
- Every system that controls drift reinjects the parent plan node **and** the global plan into every child prompt (Re3, DOC, Dramatron, AutoSurvey, AgentWrite). None relies on the plan only at the start. For the JFEC paper, each prose paragraph's prompt should therefore carry: the paper's one-paragraph contribution (L0), its section's beat list (L1), its own beat + bullets (L2), and the previous paragraph's prose.
- Parallel vs sequential writing is a real trade-off. STORM, AutoSurvey and OmniThink write sections in parallel and then run a dedup/neighbour pass. AgentWrite measured a ~6% coherence loss from parallel paragraphs, and Dramatron's parallel scenes caused continuity complaints. A reasonable design: sections in parallel (each with the full L1 outline), paragraphs within a section sequential, then one neighbour-aware smoothing pass.
- The systems that score best on factual fidelity (AutoSurvey with retrieval, plan-based retrieval, the AI Scientist's numbers that matched its logs) all tie text to **external artefacts**. Self-reflection without such ties adds little (see Section 2). Generating every number as a Python macro is the strongest version of this idea, and data-to-paper's programmatic back-tracking is the closest published analogue.
- Granularity matters. DOC shows the finest (leaf) plan items are the ones most often dropped. The paper's nested bullets are the leaves and the most likely to be silently dropped or merged during bullet -> prose expansion, so each bullet needs an explicit check.

### Gaps
- Exact STORM conditioning prompts and the "polish" step were not read from the repo ([stanford-oval/storm](https://github.com/stanford-oval/storm) not fetched). The details above come from the paper.
- SurveyX internals (AttributeTree, outline re-polishing, per-section reference binding) and Co-STORM's mind-map -> report procedure were seen only at abstract level.
- Plan-and-Write's static vs dynamic schema comparison: the abstract does not say which schema won (my recollection is static, but this is unverified).
- No system found evaluates hierarchical generation on **empirical economics/finance papers** with numeric results. All evaluations are on stories, Wikipedia-style articles, surveys or ML papers.
- data-to-paper's exact mechanism for linking manuscript numbers to code outputs was not described on the abstract page. The full paper would be needed.

## 2. Does writing from a frozen outline (claims first) beat free generation on factual accuracy and coherence? What about generate -> critique -> revise loops?

### Takeaway
Plan-first beats free generation on coherence, plan relevance, coverage and (when the plan drives retrieval) attribution, often by large margins. The outline alone does not make individual sentences more verifiable. Revision loops help style, flow and coherence, but intrinsic self-critique (no external signal) is weak or harmful for factual and reasoning errors. Loops are worth keeping only when grounded in external checks, and gains flatten after 1–2 rounds.

### Cited Findings
**Plan/outline-first vs free generation**
- Re3: +14% absolute "coherent overarching plot" and +20% premise relevance vs direct generation of the same length — [arXiv 2210.06774](https://arxiv.org/abs/2210.06774)
- DOC (more detailed outline + controller) vs Re3: +22.5 coherence, +28.2 outline relevance, +20.7 interestingness (human pairwise). Removing the detailed outliner cut relevance 64.7 -> 41.2 — [ar5iv 2212.10077](https://ar5iv.labs.arxiv.org/html/2212.10077)
- STORM: removing the outline stage cut ROUGE-1 from 45.82 to 26.77. Human editors rated organization 4.00 vs 3.25 over outline-driven RAG (p = 0.005), but verifiability was unchanged (3.80 vs 3.85, p = 0.843) — [arXiv html 2402.14207](https://arxiv.org/html/2402.14207)
- Plan-based retrieval (Godbole et al., Google, Aug 2024): a paragraph-level outline whose descriptions generate search questions raised Strict AIS attribution (e.g., News Events 82.69 vs 67.31 one-retrieval; **removing the plan dropped it to 68.59**). Humans judged plan-based outputs more informative in ~55% of comparisons vs 18%. Gains varied by model (with Mistral-7B, one plan variant did not beat a baseline). The paper cites prior work that planning before generation "can help to improve the factuality and quality of the model output" (Narayan et al. 2022 and Huot et al. 2023 QA-blueprints; Shao et al. 2024 STORM) — [ar5iv 2408.10490](https://ar5iv.labs.arxiv.org/html/2408.10490)
- AgentWrite: plan-then-write raised GPT-4o's overall LongBench-Write score 85.3 -> 87.5 (mainly from length; breadth/depth +~5%), **but coherence/clarity fell ~2%**, with occasional repetition and frequent restating/summaries — [arXiv html 2408.07055](https://arxiv.org/html/2408.07055)
- Plan-and-Write: explicit storyline planning gave more diverse, coherent, on-topic stories than no full plan — [arXiv 1811.05701](https://arxiv.org/abs/1811.05701)
- AutoSurvey (outline + per-subsection retrieval) vs naive RAG at 64k tokens: citation precision 77.41 vs 61.97, content 4.62 vs 4.19 — [arXiv html 2406.10252](https://arxiv.org/html/2406.10252)

**Factual failure modes that remain under outlines**
- STORM: ~15% of sentences unsupported by their citations; dominant error is "improper inferential linking", i.e. the model connects facts the sources do not connect — [arXiv html 2402.14207](https://arxiv.org/html/2402.14207)
- AutoSurvey: unsupported claims are 51% overgeneralization, 39% misalignment, 10% misinterpretation — [arXiv html 2406.10252](https://arxiv.org/html/2406.10252)
- AI Scientist: invented an ablation table when ablations were not run; presented negative results as positive; fixed partly by restricting to "real experimental results" — [arXiv html 2408.06292](https://arxiv.org/html/2408.06292)
- An EMNLP 2025 paper (Tu et al., "Investigating Factuality in Long-Form Text Generation") is reported to find factuality declining in later sentences of long outputs, with more unsupported claims (seen only via search snippet) — [Underline lecture page](https://underline.io/lecture/137710-investigating-factuality-in-long-form-text-generation-the-roles-of-self-known-and-self-unknown) [secondary]

**Revision loops (generate -> critique -> revise)**
- Self-Refine (Madaan et al., NeurIPS 2023): one LLM generates, critiques and refines. Across 7 tasks (dialogue to math), outputs were preferred over one-shot generation by ~20% absolute on average — [arXiv 2303.17651](https://arxiv.org/abs/2303.17651v1); [NeurIPS proceedings](https://proceedings.neurips.cc/paper_files/paper/2023/hash/91edff07232fb1b55a505a9e9f6c0ff3-Abstract.html)
- Huang et al. (Google DeepMind/UIUC, ICLR 2024): "intrinsic self-correction" without external feedback struggles on reasoning, and "at times, their performance might even degrade post self-correction". Models sometimes change correct answers to wrong ones. The authors recommend external feedback (humans, tools, data) — [arXiv 2310.01798](https://arxiv.org/pdf/2310.01798); [HF summary](https://huggingface.co/papers/2310.01798) [abstract + secondary]
- Re3's revision step (rerank for coherence and relevance, then edit for factual consistency) is part of its +14/+20 point gain — [arXiv 2210.06774](https://arxiv.org/abs/2210.06774)
- AutoSurvey: removing the reflection/refinement pass barely changed citation metrics (content 4.57 -> 4.56; structure/coherence most affected). Gains from repeated iterations flatten after round 2 — [arXiv html 2406.10252](https://arxiv.org/html/2406.10252)
- AI Scientist: per-section self-reflection plus a final section-by-section pass to remove repetition, because "first drafts tend to be verbose and repetitive". LaTeX compile errors are fed back automatically (an external check) — [arXiv html 2408.06292](https://arxiv.org/html/2408.06292)

### Inferences
- The literature supports "claims first, then prose" for **coherence and coverage**, and for **attribution when the plan drives evidence gathering**. It does not support the hope that an outline alone keeps prose factual. The prose step adds new connective claims ("improper inferential linking", "overgeneralization"). The control should therefore be a **no-new-claims rule**: every sentence of a prose paragraph must follow from its own beat + bullets + macros. This can be checked by an LLM/NLI pass that reports any sentence not supported by its bullets.
- "Frozen" in practice should mean: the human signs off on L1 (beats) and L2 (bullets), and the prose layer is a derived artefact that is regenerated from them, never edited independently. Dramatron users found the plot (beat) layer the least in need of editing. DOC shows outline errors cascade, so cheap human review time is best spent at L1/L2.
- Revision loops worth running are the ones with an external oracle: (i) LaTeX compile and lint; (ii) regex for bare digits in prose (every number must be a macro); (iii) bullet-coverage check (each L2 bullet maps to ≥1 sentence); (iv) entailment of prose by bullets; (v) reverse-outline diff (first sentence of each paragraph vs its beat). Unanchored "make it better" critiques should be capped at about 1 round, because evidence shows diminishing or negative returns.
- Null and negative results matter in finance. The AI Scientist's habit of presenting negative results as positive is a specific risk. Beats should state the sign and significance of results explicitly, and the prose check should flag hedging/upgrading words relative to the beat (e.g., "significant" where the bullet says "not significant").

### Gaps
- No controlled study was found comparing a **human-frozen** outline with an LLM-revisable outline, or measuring factual-error rates of outline-first vs free generation on documents full of numbers.
- No study was found of revision loops specifically for academic empirical papers. The AI Scientist reports failure modes, not ablations of its reflection rounds.
- Per-task breakdown of Self-Refine's ~20% and Huang et al.'s exact degradation figures not verified (abstract/summary only).

## 3. Human methods (Minto, reverse outlining, topic-sentence-first, McCloskey, Cochrane, "say the result first") and how they map to layers

### Takeaway
The human guides prescribe the same hierarchy the LLM systems found empirically. One governing claim sits at the top (Minto's governing thought, Cochrane's one-paragraph contribution). Each paragraph has one point stated in its first sentence (McCloskey, writing centres). Outline entries are substantive claims, not topic labels (McCloskey). Results come first, newspaper-style (Cochrane). This maps directly onto beat = topic sentence and bullets = paragraph body. Reverse outlining is the human version of an automated fidelity check.

### Cited Findings
- **Cochrane, "Writing Tips for Ph.D. Students" (2005)**: "Figure out the one central and novel contribution of your paper. Write this down in one paragraph." — [Marginal Revolution, 2005](https://marginalrevolution.com/marginalrevolution/2005/11/how_to_write_a_.html). "Organize the paper in 'triangular' or 'newspaper' style, not in 'joke' or 'novel' style … Notice how newspapers start with the most important part … put the punchline right up front and then slowly explain the joke … Readers don't stick around to find the punchline in Table 12." — [Rules of Exposition blog quoting Cochrane, 2012](https://rules-of-exposition.blogspot.com/2012/08/writing-tips-for-ph-d-students-by-john.html) [secondary quoting primary]. The original PDF was at `www-gsb.uchicago.edu/fac/john.cochrane/research/Papers/phd_paper_writing.pdf` (old URL, likely dead); copies at [Scribd](https://www.scribd.com/doc/61592907/Phd-Paper-Writing). Cochrane's later "writing compactly" post shows a worked example of cutting text — [Cochrane blog, Nov 2014](https://johnhcochrane.blogspot.com/2014/11/writing-compactly.html)
- **McCloskey, *Economical Writing* (3rd ed., 2019, U. Chicago Press; 35 rules)**: rule titled "A Paragraph Should Have a Point" (a paragraph is a more or less complete discussion of one topic); rule "Write Early Rather Than Late" ("Be writing all the time, working on a page or two here, a section there"). A 2000 review reports her advice that **outlines should use substantive points rather than formal ones**, e.g. replacing a heading like "Introduction" with the actual claim — [ProQuest review](https://www.proquest.com/docview/199825849) [secondary]; [CSB/SJU "Top ten rules" summary](https://employees.csbsju.edu/jolson/ECON384/McCloskeyEconomicalWriting.htm) [secondary]; [publisher listing](https://bookshop.org/p/books/economical-writing-third-edition-thirty-five-rules-for-clear-and-persuasive-prose-deirdre-nansen-mccloskey/2e8d82a7d69715da)
- **Minto, *The Pyramid Principle***: a single governing thought at the top. Vertical logic: each level summarises or supports the level above (a question-answer dialogue). Horizontal logic: siblings form a MECE grouping (mutually exclusive, collectively exhaustive), ordered by time, structure or importance, and argued deductively or inductively. SCQA (Situation, Complication, Question, Answer) frames the introduction — [ThinkInsights: Pyramid Principle](https://thinkinsights.net/strategy/pyramid-principle); [ThinkInsights: SCQA](https://thinkinsights.net/strategy/scqa-logic) [secondary; book not consulted; sources disagree on whether it originated in the 1960s or 1970s at McKinsey]
- **Keith Head, "The Introduction Formula"**: Hook -> Question -> Antecedents -> Value-added (about three contributions; "probably the most important paragraph for persuading referees") -> Road-map (customised, naming "landmarks" such as results; avoid generic outlines). "This paper addresses the question" should appear at the end of paragraph 2 or start of paragraph 3. Head advises writing the introduction first and revising it as other sections are drafted — [Head, UBC](https://blogs.ubc.ca/khead/research/research-advice/formula)
- **Bellemare, "How to Write Applied Papers in Economics" (2020)**: lists the standard applied-paper structure and builds on Head's formula (hook, then a clearly stated research question) — [Thomas Sos blog checklist, Oct 2025](https://thomassoseco.blogspot.com/2025/10/how-to-write-applied-papers-in.html) [secondary; the PDF mirror returned 404]
- **Reverse outlining** (writing-centre practice): after drafting, write each body paragraph's topic sentence and purpose. Record whether the topic sentence is at the start, and write one if it is missing. Check which evidence follows the topic sentence's "roadmap" and which does not. Then regroup the summaries into blocks to reorganise — [UMN Crookston](https://crk.umn.edu/sites/crk.umn.edu/files/2023-03/how-to-make-reverse-outline.pdf); [Antioch VWC](https://www.antioch.edu/wp-content/uploads/2017/02/VWC-The-Reverse-Outline.pdf); [UT Austin UWC](https://uwc.utexas.edu/wp-content/uploads/Reverse-Outlining-1-1.docx); [Caltech Hixon](https://writing.caltech.edu/documents/29881/Revising_with_Reverse_Outlines.pdf); [Oregon State](https://writingcenter.oregonstate.edu/reverse-outlining). UT Austin notes that "a buried (or non-existent) topic sentence will make a paragraph difficult to summarize".

### Inferences
Proposed layer mapping for the JFEC paper (synthesis, not from any one source):

| Layer | Human-method analogue | LLM-system analogue | Content rule |
|---|---|---|---|
| L0: contribution paragraph / abstract | Cochrane's one-paragraph contribution; Minto governing thought; Head's Value-added | Dramatron logline; DOC premise | one paragraph; states the main result with macro numbers |
| L1: beats (top-level `\item \textbf{label.} claim`) | McCloskey's substantive (claim, not topic) outline points; Minto's key line (MECE siblings); topic sentence | Dramatron scene beat; DOC depth-1/2 nodes; AgentWrite "main point" | one beat = one paragraph; a full declarative claim, result first; siblings MECE |
| L2: nested bullets | paragraph body / evidence (Minto vertical support) | DOC leaves; AgentWrite paragraph content | each bullet = one supporting fact, number (macro), caveat or citation; no new claims |
| L3: appendix | supporting detail referenced from L2 | — | linked by `\ref`, never restated in prose |
| L4: prose | reverse-outline-consistent paragraph | drafted text | first sentence ≈ beat; body realises bullets in order; no unlisted claims |

- Cochrane's "newspaper style" also applies within a paragraph: the beat (result) comes first and the bullets explain it. That fits the existing `\textbf{label.} claim` format.
- McCloskey's "substantive not formal" rule implies beat labels should be short claims ("Variance risk premium is negative at 0DTE") rather than topics ("Variance risk premium"). The label is the human review surface.
- A reverse outline of the generated prose should reproduce L1 exactly. That gives a mechanical fidelity test: extract each paragraph's first sentence and compare it to its beat.

### Gaps
- Thomson ("A Guide for the Young Economist") and Nikolov (economics writing tips) were not consulted. No primary text of Minto's book or Bellemare's paper was read.
- I found no empirical study measuring whether topic-sentence-first paragraphs improve reader comprehension of economics papers. The guides are expert opinion.

## 4. Practical patterns for tying each prose paragraph to the beat it implements (IDs, anchors, one paragraph per beat) so changes propagate

### Takeaway
None of the research systems implements incremental propagation (beat edit -> regenerate only affected prose). Dramatron explicitly lacks a propagation mechanism. The building blocks do exist: one-unit-per-plan-node generation (DOC, AgentWrite, Dramatron), plan-node-scoped context, neighbour-aware smoothing (AutoSurvey), and programmatic provenance from results to text (data-to-paper, the AI Scientist's "only real results" rule). A practical design combines stable beat IDs, content hashes and a per-paragraph regenerate-and-verify loop.

### Cited Findings
- One generation unit per plan node, with a stop rule tied to that node: DOC writes passages per outline item and moves to the next item when relevance/coherence to the current item passes a threshold and stops improving. The next item is given as look-ahead, but control is applied only to the current item — [ar5iv 2212.10077](https://ar5iv.labs.arxiv.org/html/2212.10077)
- One paragraph per plan entry with an explicit main point and word budget, written in order with all previous paragraphs in context — [arXiv html 2408.07055](https://arxiv.org/html/2408.07055)
- One scene per beat, with the current and previous beats in the prompt to fix continuity. Users can edit any level, but no downward propagation mechanism is described — [ar5iv 2209.14958](https://ar5iv.labs.arxiv.org/html/2209.14958)

- Per-section evidence retrieval keyed to the section heading, then dedup across sections and a lead section written last — [arXiv html 2402.14207](https://arxiv.org/html/2402.14207); [OmniThink](https://arxiv.org/html/2501.09751v5)

- Restricting the writer to "real experimental results in the form of notes and figures generated from code", with automatic LaTeX compile/lint feedback; numbers in the main table then matched the logs — [arXiv html 2408.06292](https://arxiv.org/html/2408.06292)
- Reverse-outline checks (topic sentence present and first; evidence follows the topic sentence's roadmap) — [Antioch VWC](https://www.antioch.edu/wp-content/uploads/2017/02/VWC-The-Reverse-Outline.pdf); [UT Austin UWC](https://uwc.utexas.edu/wp-content/uploads/Reverse-Outlining-1-1.docx)

### Inferences
Concrete pattern for the user's LaTeX + Claude Code setup (design synthesis; not validated by any cited study):
1. **Stable beat IDs.** Each beat gets an immutable ID independent of its position and label, e.g. `\beat{b:vrp-sign}{VRP sign.}{claim…}`, with nested bullets as `\bul{b:vrp-sign.1}{…}`. The prose paragraph is wrapped as `\begin{para}{b:vrp-sign} … \end{para}` (or a `% beat: b:vrp-sign` comment at its top). One beat maps to exactly one paragraph, which follows DOC/AgentWrite/Dramatron.
2. **Content hash for staleness.** Store `hash(beat text + bullet texts + macro names used)` in the prose block (e.g. `% src-hash: …`). A script lists paragraphs whose stored hash ≠ current hash. Only those are regenerated, plus a smoothing pass over their immediate neighbours (AutoSurvey's neighbour refinement). Changing a beat then propagates to exactly one paragraph and its transitions.
3. **Context per regeneration**: L0 contribution + the section's L1 beat list + this beat's L2 bullets + the previous paragraph's final prose + the next beat as look-ahead (DOC). Write paragraphs within a section sequentially (AgentWrite: parallel loses ~6% coherence). Sections can run in parallel.
4. **Numbers only via macros.** Lint: prose may contain no bare digits outside macros, `\ref`/`\cite` and an allowlist (years, "two", etc.). Every macro used in prose must appear in that paragraph's bullets. This is the data-to-paper / AI Scientist provenance idea made mechanical, and it blocks the "invented ablation table" failure.
5. **Fidelity checks after generation, all with external oracles:** (a) reverse outline: the first sentence must paraphrase the beat (LLM/NLI judge); (b) coverage: each bullet ID is realised by at least one sentence (ask the generator to emit a hidden sentence->bullet map, e.g. `%<- b:vrp-sign.2`); (c) no-new-claims: every sentence must be entailed by beat + bullets (flag STORM-style "improper inferential linking" and AutoSurvey-style "overgeneralization"); (d) sign/significance consistency (no upgrading "not significant" to "significant"); (e) LaTeX compile. A failure triggers regeneration of that paragraph only, capped at 1–2 rounds.
6. **Human review surface = L1 (+ L2 on demand).** Dramatron users barely edited the beat layer and DOC shows outline errors cascade. The human therefore approves beats and bullets, and prose is a build artefact that is never hand-edited. If a human edits prose, a reverse-outline diff should report it so the edit is pushed back into the beat/bullet.
7. **Layer toggles** follow directly: L1 = render only `\beat` labels + claims; L2 = + `\bul`; L3 = + appendix pointers; L4 = render `para` environments instead. All four can be produced from one source via LaTeX conditionals or the existing auto-generated review layers.

### Gaps
- No published system or study implements or evaluates incremental beat->prose propagation with IDs and hashes. The pattern above is an engineering inference from the cited building blocks.
- No source was found on semantic line breaks, literate-programming, or docs-as-code practice applied to academic paper layering (not searched in depth within the tool budget).
- No evidence was found on how far LLM judges can be trusted for "first sentence paraphrases beat" or "sentence entailed by bullets" checks on technical finance prose. AutoSurvey's LLM-judge vs expert rank correlation was only moderate (Spearman ρ = 0.54) — [arXiv html 2406.10252](https://arxiv.org/html/2406.10252).
