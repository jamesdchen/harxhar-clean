# Overleaf sync: flat `main.tex` <-> the macro / generator system (spec, 2026-10-20)

The paper of record is `writeup/paper_rehaul.tex`. Its preamble `\input`s twelve macro-only number files from
`writeup/generated/` (each written by a `writeup/make_*.py` generator), and its body `\input`s the section files
`writeup/rehaul/*.tex`. Some section files `\input` generated floats (`writeup/generated/rehaul_*.tex` tables).
The paper is built from `writeup/` (pdflatex, bibtex, pdflatex x2), so every relative path resolves against
`writeup/`.

Two scripts, both in `writeup/overleaf_sync/`, both standard-library Python 3 (no third-party packages):

* `flatten.py`: current system -> one flat `main.tex` that Overleaf users edit like any LaTeX file:
  * no live `\input`;
  * no number macros: every macro defined in a preamble number file is replaced by its literal expansion.
  It also writes a map file that records where every character of `main.tex` came from.
* `unflatten.py`: an edited `main.tex` plus the map -> edits applied back to the hand-written source files
  (`paper_rehaul.tex`, `rehaul/*.tex`). Edits to generated material are never applied. They are reported as
  conflicts, together with the generator to change.

House rules that both scripts respect:
* never hand-edit a generated file (`writeup/generated/*`): change its generator;
* park replaced text in dated comments rather than deleting it;
* every number in the prose comes from a generated macro;
* never run `writeup/make_rehaul_data_methods.py`.

## 1. Terms

* **Hand-written source**: `paper_rehaul.tex` and every `rehaul/*.tex` that is inlined.
* **Number file**: a file `\input` by the preamble of `paper_rehaul.tex`, at the time of writing these twelve:
  `close_main_numbers`, `fig_qlike_sharpe_numbers`, `rehaul_results_numbers`, `rehaul_econ_numbers`,
  `rehaul_fi_numbers`, `rehaul_app_numbers`, `rehaul_dm_numbers`, `buckets_numbers`,
  `close_murphy_splits_numbers`, `close_compounding_numbers`, `close_shift_test_numbers`, `rehaul_oos_numbers`.
  Detect them by parsing the preamble; do not hard-code the list.
* **Number macro**: a control word defined in a number file by `\newcommand`, `\providecommand` or `\renewcommand`,
  with or without `*`, all without arguments. Several files use `\providecommand{\X}{}\renewcommand{\X}{value}`; the
  last definition wins, in preamble `\input` order. Two definitions take arguments: `\ser` [2] and `\serx` [3], the
  raw-name switch. They are **not** number macros, and they stay as they are; `paper_rehaul.tex`'s preamble defines
  them too.
* **Generated float**: any `writeup/generated/*.tex` that is `\input` from a hand-written source, not from the
  preamble. It is inlined, but it remains generated: it is never edited back.
* **Generator** of a generated file: the `writeup/make_*.py` (or `experiments/*.py`) named in its first comment
  lines, for example `% AUTO-GENERATED by writeup/make_rehaul_oos_table.py` or `% generated by writeup/make_...py`.
  Use null if none is found.

## 2. TeX lexing rules (both scripts)

* **Comment.** A `%` that is not escaped (it is preceded by an even number of backslashes) starts a comment that runs
  to the end of the line, the newline included. Comment text is copied verbatim:
  * macros in comments are not expanded;
  * `\input` in comments is not inlined.
* **Control word.** A backslash followed by the maximal run of ASCII letters `[A-Za-z]+`, so `\rhfiP` and
  `\rhfiPredGap` are different names. A control symbol (a backslash plus one non-letter, such as `\%`, `\,` or `\\`)
  is never a macro call.
* **Space swallowing**, which mimics TeX exactly. After a number-macro call written without braces, TeX skips the
  following spaces and tabs. If it then meets a single end-of-line and the next line is not blank, that end-of-line
  is dropped too. If the next line is blank, keep the newlines: the paragraph break must survive.
* **Empty group.** A call followed immediately by `{}` consumes the `{}`.
* **What a call covers in the source.** Its source range is the control word plus whatever was consumed (`{}` or the
  swallowed spaces and end-of-line).
* **Writing the expansion.** The expansion is the macro's value, fully expanded. Number macros inside a value are
  expanded recursively; other control sequences in a value (`\ensuremath`, `\ser`, `{,}` and so on) are kept. If the
  expansion ends in a control word and the next source character is a letter, append `{}` so that the word does not
  merge with that letter.

## 3. `flatten.py`

CLI:
`python writeup/overleaf_sync/flatten.py --out DIR [--map writeup/overleaf_sync/map.json] [--entry writeup/paper_rehaul.tex] [--check]`

It writes `DIR/main.tex`, `DIR/references.bib` (a copy) and any figures referenced by live
`\includegraphics{...}`. Figures keep their path relative to `writeup/`, resolved with the default extensions
`.pdf`, `.png`, `.jpg` and `.eps`, and `\graphicspath` if one is set.

Transformations:
1. **The preamble of `paper_rehaul.tex`** (everything before `\begin{document}`) is copied verbatim. Each live
   `\input{generated/<number file>}` line, its newline included, is removed and recorded as a `drop` segment.
2. **Every live `\input{X}`** (`X` with or without `.tex`, resolved against `writeup/`) is replaced by:
   * a synthetic begin marker line `%% >>> begin X.tex (<hand-written | generated by <generator>>)`;
   * the file's content, processed recursively;
   * a synthetic end marker line `%% <<< end X.tex`.

   The `\input{X}` call text is a zero-length `drop` segment. Inlining keeps TeX's behaviour: the file's content
   followed by the rest of the calling line.
3. **Guard lines** of the form `\ifdefined\NAME\else\input{generated/...}\fi`, where the `\input` names a number
   file, are removed (`drop`). They appear in generated floats, and live ones may appear in section files.
4. **Number-macro calls** are replaced by their expansion (`macro` segments). This applies everywhere outside
   comments, including inside `\iffalse ... \fi` blocks and inside generated floats.
5. **A synthetic header comment** at the very top of `main.tex`. It says that the file was generated by
   `flatten.py` from commit `<sha>` (with `+dirty` if the working tree was not clean), that edits are brought back
   by `unflatten.py`, and that numbers and tables come from generators, so editing them in Overleaf is flagged and
   not applied.
6. **Everything else** is copied verbatim (`src` segments), comments included.

`--check` (and the agent's acceptance test):
* In a temporary copy of `DIR` containing `main.tex`, `references.bib` and the figures, build `main.tex` with
  pdflatex, bibtex, pdflatex x2.
* Build `writeup/paper_rehaul.tex` the same way, in a temporary copy of `writeup/` so that tracked build files are
  not touched.
* `pdftotext` both PDFs. The texts must be identical, and the page counts must be equal.
* Also assert that the live text of `main.tex` has no `\input`, `\include` or `\InputIfFileExists`, and no control
  word that is a number-macro name.

## 4. The map file (JSON, UTF-8, written by `flatten.py`)

```json
{
  "version": 1,
  "created": "ISO-8601 UTC",
  "entry": "paper_rehaul.tex",
  "source_commit": "<git sha of HEAD>", "source_dirty": false,
  "flat_file": "main.tex",
  "flat_sha256": "<sha256 of flat_text>",
  "flat_text": "<the exact text written to main.tex>",
  "sources": { "<path relative to writeup/>": {"sha256": "...", "text": "<full text as read>", "kind": "hand|generated|numbers"} },
  "macros": { "<name without backslash>": {"value": "<raw value>", "expanded": "<flat expansion>", "file": "generated/x.tex", "generator": "writeup/make_x.py"} },
  "segments": [ {"flat": [a, b], "kind": "src|macro|gen|synthetic|drop", "file": "<rel path or null>", "src": [s, e], "macro": "<name or null>", "generator": "<or null>"} ]
}
```

Segment invariants:
* Segments are sorted by `flat[0]`. Nonzero-length segments tile `[0, len(flat_text))` exactly. `drop` segments
  have `a == b`.
* `src`: `flat_text[a:b] == sources[file].text[s:e]`, and `file` is hand-written.
* `macro`: `flat_text[a:b] == macros[name].expanded` (plus an appended `{}` if rule 2 added one).
  `sources[file].text[s:e]` is the call as written. `file` may be hand-written or generated.
* `gen`: text that comes from a generated float. Its verbatim parts and the expansions of the macros inside it may
  be split into several `gen` segments or kept as one; each has `file` set to the generated file and `generator`
  set.
* `synthetic`: flattener text (header, markers); `file` is null.
* `drop`: source text removed with no flat counterpart (`sources[file].text[s:e]`).

## 5. `unflatten.py`

CLI:
`python writeup/overleaf_sync/unflatten.py --main PATH/main.tex [--map writeup/overleaf_sync/map.json] [--date YYYY-MM-DD] [--dry-run] [--report writeup/overleaf_sync/REPORT.md]`

Steps:
1. **Diff.** Let `base` be `map.flat_text` and `edited` the new `main.tex`. If they are equal, report "no changes"
   and exit 0. Otherwise diff `base` against `edited` by lines (`difflib.SequenceMatcher`, `autojunk=False`). Each
   non-equal block becomes one hunk `(a, b, new_text)` in base character coordinates. Trim the common prefix and
   suffix characters of the old and new text of the hunk, so that an edited word does not drag in unchanged
   neighbouring numbers.
2. **Classify each hunk** by the segments it overlaps. An insertion (`a == b`) attaches to the `src` segment ending
   at `a`, else to the `src` segment starting at `a`.
   * **Only `src` segments, plus optionally `macro` segments of the same hand-written file between them: apply.**
     * The source range runs from the start of the first overlapped segment's mapped position to the end of the
       last.
     * The new source text is `new_text` with every overlapped macro's expansion re-linked: search the expansions
       in order, left to right, and replace each with that macro's original call text from the source.
     * If a macro's expansion no longer appears, the hunk is a **number conflict** and is not applied. Report the
       macro, its old value, the new text, the macro's file and its generator.
   * **Any `gen` segment overlapped: generated conflict**, not applied. Report the generated file and the generator
     to change.
   * **A `synthetic` segment, a `drop` segment with non-empty source text strictly inside the hunk, or `src`
     segments from more than one file: structural conflict**, not applied.
3. **Apply, file by file, with parking.**
   * Merge the edits of a file that touch the same or adjacent lines.
   * For each merged edit, expand to whole source lines.
   * If every non-blank old line is a comment line (`^\s*%`), or the old block is blank (a pure insertion), write
     the new block directly.
   * Otherwise write:
     * `<indent>% <date> (overleaf): parked -- edited in Overleaf. Was:`
     * the old lines, each as `<indent>% <old line without its indent>`;
     * the new block.
   * A pure deletion leaves only the parked comment.
   * `date` defaults to today, in UTC.
4. **Concurrency.**
   * If a source file's current sha256 equals `map.sources[file].sha256`, edit it in place.
   * Otherwise write the patched base to a temporary file and run
     `git merge-file -p <current> <base> <patched>`. Write the result only if the merge is clean. On a conflict,
     record a merge conflict and leave the file untouched.
5. **Warnings**, which do not block anything: an applied insertion that adds new digits to prose outside comments
   is flagged, because the house rule wants every number in prose from a generated macro.
6. **Report** (markdown):
   * the applied edits, as file:line with a short old -> new;
   * every conflict, with its `main.tex` line number, kind, old and new text, and the macro or generator to change;
   * a closing note: "run flatten.py again; conflicting edits to numbers or tables will be overwritten in `main.tex`
     by the next flatten unless the generator changes."
   
   Exit 0 if there are no conflicts and 2 if there are conflicts. Non-conflicting edits are still applied, unless
   `--strict` is given, which applies nothing when any conflict exists. `--dry-run` writes nothing except the
   report.

## 6. Acceptance tests

* **Round trip, no edit.** `flatten`, then `unflatten` on the unchanged `main.tex`: "no changes", and no file
  modified.
* **Prose edit.** Change one word in an introduction sentence that contains number macros. The edit is applied to
  `rehaul/01_introduction.tex`, the macros stay intact, the old line is parked with the date, and a re-flatten shows
  the new word.
* **Number edit.** Change a literal number that came from a macro (for example the trading-day count 1,082):
  number conflict, nothing applied, and the report names the macro and its generator.
* **Table edit.** Change a cell of Table 1 (`generated/rehaul_results_oos.tex`): generated conflict naming
  `writeup/make_rehaul_oos_table.py`.
* **Inserted sentence.** Add a new sentence in a section: inserted, with no parking if it is on its own new line;
  digits in it raise the warning.
* **Edit inside a comment.** Applied directly, with no parking.
* **Concurrent change.** The source file changes after flatten in a different place: three-way merge, clean.
* After the applied tests, the paper still compiles.

Run all tests on temporary copies of `writeup/`, never on the real section files.

## 7. Clarifications from the implementation (2026-10-20)

The scripts follow sections 1-6 with these additions. Each one fills a case the text above did not cover.

`flatten.py`:
* When a dropped end of line is followed by an indented line, the call also swallows that indentation, as TeX does.
  The call's `src` range includes it.
* `{}` is also appended after a consumed `{}` that is followed by a blank, if the expansion ends in a control word.
  If the expansion is empty, the text before it is what gets checked.
* When only blanks follow `\input{X}` on its line, the end marker has no newline of its own: the calling line's
  newline (`src`) ends it. A blank line there would be read by TeX as a paragraph break.
* Number-macro calls inside a generated float are `gen` segments with `macro` set and `src` covering the call. Any
  edit there is a generated conflict.
* Synthetic segments have `src: null`.
* Definitions follow TeX: `\providecommand` keeps an existing name, and a repeated `\newcommand` keeps the first.
* `--keep-builds` keeps the temporary build directories of `--check`.
* Exit codes: 0 for OK, 1 for a failed check, 2 when the source cannot be flattened. Flatten refuses (exit 2):
  * a number macro right after `\def`, `\let`, `\ifdefined` or `\newcommand`;
  * a live `\include`, `\InputIfFileExists` or `\endinput`;
  * an `\input` without braces;
  * anything other than definitions in a number file.

`unflatten.py`:
* An insertion strictly inside a segment belongs to that segment.
* Digits typed against a macro's value (`1{,}082` -> `1{,}0825`) are a number conflict, not an insertion next to the
  macro.
* The digit warning covers any applied edit that adds a number. It ignores comments and `\label`, `\ref` and `\cite`
  arguments, and names any existing macro with the same value.
* Each parked old line keeps its own indent before `% `.
* Exit codes: 0 for no conflicts, 2 for conflicts, and 1 for an error, such as a map that fails the section 4
  checks. The map is validated before anything is planned.
* `--map` and `--report` default to `<root>/overleaf_sync/`, and `--root` defaults to `writeup/`.
* A byte-order mark, CRLF line endings or a dropped final newline in `main.tex` are not counted as edits.
* All files are planned in memory before any is written, so `--strict` can hold back every edit.

Known limits:
* One hunk is one block of changed lines, so a number edit next to a prose edit in the same block blocks both.
* Deleting a line that contains a macro value is a number conflict.
* Text-valued macros (for example `\rhfiRfTopOne` = "HAR components") count as numbers.
* Re-linking can bind a macro to an identical literal typed earlier in the same hunk.
* The lexer ignores catcode changes and verbatim environments.

Tests: `test_unflatten.py` has 35 fixture tests. `test_roundtrip.py` runs the real flatten on a temporary copy of
`writeup/` and covers the 14 cases of section 6 plus a compile step.

Output names (2026-10-20, user): `flatten.py --name NAME` writes the flat file under that name, which is also
`flat_file` in the map. `--bib-suffix S` writes each `.bib` of a live `\bibliography` as `<name>S.bib`, and writes the
`\bibliography` argument with those names. The written argument is a `drop` segment and the renamed list a
`synthetic` one, so an Overleaf edit of it is a structural conflict. The Overleaf project's own `main.tex` and
`references.bib` stay untouched (`main2.tex`, `references2.bib`).
